Redesigned and rebuilt ShipStage, a multi-carrier shipping back office (web): new navigation, UI and frontend on top of the existing API.

Overview

ShipStage is a back office for online shops that ship parcels with several carriers (UPS, DHL, GLS, IDS): create and pay for shipments from one balance, track them, schedule pickups and handle returns. I redesigned the whole dashboard and rebuilt its frontend from scratch.

Challenges

  1. Rethink the whole dashboard without adding a new product on top: same functionality, but clearer and faster to use.
  2. Refresh the visual style and the navigation, which no longer matched the platform’s growth.
  3. Keep the existing Django REST API. The new frontend had to fit the API as it was.
  4. Serve repetitive, batch-like work: CSV import, cart, daily pickups. Speed and scanability matter more than ornament.

Solution

  1. New information architecture. Navigation rebuilt around merchant jobs: Dashboard, Packages (Unpaid, Completed, Cart, Import CSV), Create shipment, Pickups, Finance, Return Portal, Settings.
  2. New visual language and design system. Shared components and tokens, light and dark themes, English and German. Empty, error and loading states designed as part of the product.
  3. Work that waits is surfaced. What needs the merchant’s attention shows up on the dashboard instead of being buried in sections.
  4. New frontend architecture. Next.js 16, React 19 and TypeScript with a tRPC layer in front of the Django REST API, TanStack Query for data, shadcn/ui and Tailwind 4 for the UI.

Results

I redesigned the whole back office and rebuilt it on a modern stack. The new version is in its final stage before release.
